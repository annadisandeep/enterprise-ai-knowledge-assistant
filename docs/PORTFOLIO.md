## Project description (for a personal site)

**Enterprise AI Knowledge Assistant** is a full-stack, cloud-deployable Retrieval-Augmented Generation (RAG) application. Users upload their own documents (PDF, TXT, Markdown) and ask questions in plain English; the system answers using **only** the content of those documents and returns **verifiable citations** for every response. It combines a FastAPI backend, a React + TypeScript frontend, local semantic embeddings, a Chroma vector database, and Google's Gemini model, wrapped in a clean service architecture.

What sets the project apart is its focus on **engineering discipline around AI**, not just calling an LLM. Retrieval is boundary-aware and threshold-filtered; **citations are assembled from the retrieval layer so the model physically cannot fabricate a source**; and the system returns an honest "I don't know" when the documents don't contain an answer. Security is treated as a first-class concern — API-key auth with constant-time comparison, strict CORS, upload magic-byte validation, SHA-256 duplicate detection, and layered prompt-injection defenses — and the codebase is honest about its limitations rather than overclaiming.

The project is also **operationally complete**: it ships with a fast, deterministic test suite (67 backend + 13 frontend tests; external AI is mocked so CI is free and reproducible), GitHub Actions CI with dependency scanning, Docker/Compose for local parity, and **Terraform-based Infrastructure-as-Code** for a Google Cloud deployment (Cloud Run, Artifact Registry, Secret Manager, and a GCS bucket for durable vector storage). It is a production-**oriented** demonstration of how to design, test, secure, and ship an AI feature end-to-end.

**What has been verified:** the full RAG pipeline, the Gemini integration (`gemini-3.5-flash-lite`, live API) and the UI were run locally and are shown in the README screenshots. The Terraform configuration validates but has not been applied to a real GCP project, and the manual deploy workflow has never been triggered.

## Skills demonstrated

- **Retrieval-Augmented Generation (RAG):** chunking strategy, embeddings, vector search, context assembly, grounded prompting, citation integrity, no-answer handling.
- **LLM integration:** Google Gemini via the official `google-genai` SDK; a pluggable provider abstraction with a mock for testing.
- **Backend engineering:** Python 3.12, FastAPI, Pydantic v2, dependency injection, clean service decomposition, typed schemas, robust error mapping.
- **Frontend engineering:** React + TypeScript + Vite + Tailwind, sanitized Markdown rendering, environment-driven API configuration.
- **Vector databases:** Chroma persistence, cosine similarity, similarity thresholds.
- **Security engineering:** API-key auth, CORS policy, upload validation (size/type/magic-byte), binary rejection, prompt-injection mitigations, non-root containers, honest threat/limitation analysis.
- **Testing:** pytest + vitest, deterministic mocking of external AI, a semantic evaluation set with graceful skips, coverage.
- **DevOps / CI-CD:** Docker, docker-compose, GitHub Actions, dependency scanning (pip-audit, npm audit).
- **Cloud & IaC:** Terraform for GCP — Cloud Run (scale-to-zero), Artifact Registry, Secret Manager, GCS-backed persistence, Workload Identity Federation.
- **Technical writing:** thorough, honest, cross-linked documentation.

## Talking points for interviews

**Architecture decisions**
- Why **citations are built from retrieval, not model output** — an integrity guarantee that defeats citation hallucination.
- Why metadata lives in a **JSON registry** while vectors live in **Chroma** — a system-of-record vs. a specialized search index.
- The **pluggable embedding and LLM abstractions** — enabling free, deterministic CI (hashing + mock) alongside a realistic semantic path.
- The **grounded prompt + explicit no-answer** design — choosing honesty over hallucination.

**Tradeoffs**
- **gcsfuse-backed Chroma on stateless Cloud Run** — great for a cheap single-instance demo, but not strongly consistent or high-throughput; I can articulate exactly when and why I'd move to a managed vector DB.
- **Single shared API key and one shared knowledge base** — I know this isn't multi-tenant and can explain the path to SSO/OIDC, RBAC, and per-user ACLs.
- **Prompt-injection mitigations reduce but don't eliminate risk** — I treat it as an open problem and layer defenses rather than claiming it's "solved."
- **Shipping a key to the SPA** via `VITE_API_KEY` is a demo convenience; a real system needs a backend-for-frontend or gateway.

**What I'd do next**
- Add **SSO/OIDC** auth, **per-user document ACLs**, and **RBAC**.
- Add **rate limiting / Cloud Armor** at the edge.
- Swap file-backed Chroma for a **managed vector database**.
- Add **audit logging**, **secrets rotation**, and **DLP** on uploads.
- Expand the **evaluation harness** into a proper retrieval-quality benchmark with metrics.
- Add **streaming responses** and conversation memory.
